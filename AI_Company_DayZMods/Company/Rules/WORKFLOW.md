# Рабочий процесс и взаимодействие агентов

## Задача и её поля
ID (`T-XXXX`) · название · описание · ответственный · тип (research, dev, config, art, build, qa, media, planning, hr, ops) · приоритет · статус · срок · зависимости · бюджет токенов · результат · файлы · отчёты о проверке · журнал. Всё хранится в `Company/Tasks/tasks.json`, витрина — `Company/Tasks/BOARD.md`.

## Статусы и переходы
| Из | Можно перейти в |
|---|---|
| NEW | PLANNING, RESEARCH, IN_PROGRESS, BLOCKED |
| PLANNING | NEW, RESEARCH, IN_PROGRESS, BLOCKED |
| RESEARCH | PLANNING, IN_PROGRESS, REVIEW, BLOCKED |
| IN_PROGRESS | RESEARCH, REVIEW, BLOCKED |
| REVIEW | TESTING, FIXING, COMPLETED, BLOCKED |
| TESTING | FIXING, COMPLETED, BLOCKED |
| FIXING | REVIEW, TESTING, BLOCKED |
| BLOCKED | любой рабочий статус (после снятия блокировки) |
| COMPLETED | FIXING (только переоткрытие с причиной) |

Гейты проверяет `./dzm`, обойти их нельзя:
- в рабочие статусы (RESEARCH … COMPLETED) — только когда все зависимости COMPLETED;
- в REVIEW — только с заполненным результатом;
- в COMPLETED — только после PASS-проверки другим сотрудником; задачи dev, config, art, build закрывает только отдел QA;
- BLOCKED и переоткрытие — только с причиной (`--note`).

## Приоритеты и сроки
P0 — блокирует заказчика или сервер, делать сейчас · P1 — текущий этап проекта · P2 — плановое · P3 — бэклог и обучение. Срок ставит планировщик. Просроченные задачи видны в `./dzm status` и в отчёте CEO.

## Поток проекта
Заказ → `/new-project` → Э0 (реализуемость) → утверждение заказчиком → планировщик ставит задачи → исполнители → `/qa-gate` → CEO принимает → передача заказчику. Этапы подробно описаны в `.claude/agents/project-planner.md`.

## Как агенты взаимодействуют (что реально работает)
1. **CEO → агент.** Инструмент Agent: задание с ID задачи, путями и критерием готовности. Агент отвечает «Коротким отчётом» (формат в CLAUDE.md).
2. **Руководитель → помощник.** Вложенный вызов Agent, до 3 уровней ниже CEO. Работает только у агентов, которым выдан инструмент Agent (руководители QA, Research, Engineering, 3D, Media).
3. **Продолжение диалога в сессии.** SendMessage возобновляет уже работавшего агента с его контекстом.
4. **Асинхронно и между сессиями.** Комментарии в задачах (`./dzm task comment T-XXXX --by A --to B --text "..."`) и входящие (`./dzm inbox B`), результаты в файлах задачи, знания в Knowledge_Base, личный опыт в памяти агента.
5. **Передача работы.** Исполнитель переводит задачу в REVIEW с результатом и файлами и оставляет комментарий следующему (`--to`).

Агенты не видят историю чата CEO: всё нужное передаётся в задании или лежит в файлах.

## Отчётность
- После каждого запуска агента CEO выполняет `./dzm run log` (токены из usage результата).
- Конец сессии: `./dzm report daily --save`. По запросу заказчика или раз в неделю: `./dzm report ceo --save` (формат из 10 разделов).
