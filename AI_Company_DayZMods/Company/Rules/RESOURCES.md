# Ресурсы: токены, модели, параллельность

## Модели
| Модель | Когда использовать | Агенты по умолчанию |
|---|---|---|
| opus | архитектура, сложный Enforce Script, разбор тяжёлых ошибок, спорные технические решения | lead-engineer |
| sonnet | основная работа: планирование, исследования, конфиги, 3D-скрипты, QA, медиа | большинство |
| haiku | рутина по чётким инструкциям: монтаж по ТЗ, форматирование, массовые однотипные правки | video-editor |

Модель для конкретного запуска может поменять CEO или планировщик (параметр model при делегировании). Факт фиксируется в `./dzm run log --model`.

## Бюджеты задач
S ≤ 30k · M ≤ 80k · L ≤ 200k токенов (поле задачи `--budget`). Задачу больше L делим. Перерасход виден в разделе 9 отчёта CEO.

## Правила
1. Один исполнитель на задачу. Одинаковая работа двум агентам — только для независимой перекрёстной проверки и только по решению CEO.
2. Параллельно запускаем только независимые задачи, по умолчанию не больше 3 агентов одновременно.
3. Сначала база знаний: найденное однажды не ищется снова.
4. Между агентами — короткие отчёты (формат в CLAUDE.md), подробности — в файлах.
5. В задании агенту — только нужный контекст: ID задачи, пути, критерий готовности. Файлы целиком в промпт не пересылаем.
6. Отчёты и сводки генерирует `./dzm` без участия модели. Модель добавляет только выводы.
7. Учёт: после каждого запуска CEO пишет `./dzm run log`. Токены берутся из usage в результате агента. Расход основной сессии заказчик видит в `/usage`.
8. Регулярные запуски по расписанию — только по решению заказчика: каждый такой запуск тратит токены, даже если работы нет.
