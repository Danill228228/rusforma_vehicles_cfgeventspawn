### BUG-0001 — cfgeventspawns: событие VehicleSpawnPoints не закрыто тегом </event>, XML не парсится
1. **Название:** cfgeventspawns: событие VehicleSpawnPoints не закрыто тегом </event>, XML не парсится
2. **Критичность:** S1 (Критическая)
3. **Условия воспроизведения:** python3 -c "import xml.etree.ElementTree as E; E.parse('rusforma_vehicles_cfgeventspawn')" -> ParseError: mismatched tag: line 332, column 2
4. **Причина:** Открытый на строке 3 <event name="VehicleSpawnPoints"> не закрыт: после последней pos (строка 45) сразу идёт комментарий и следующий <event> (строка 47); 41 событие VehicleCrSk_* оказываются вложенными
5. **Файл и место:** rusforma_vehicles_cfgeventspawn:45-47
6. **Предлагаемое исправление:** Вставить </event> после строки 45 (перед комментарием LUAZ_969); повторить парсер и сравнение с эталоном BI. Сервер при битом XML может проигнорировать файл целиком (не проверено, нужен сервер)

### BUG-0002 — cfgeventspawns: все 123 точки событий VehicleCrSk_* совпадают с 21 точкой VehicleSpawnPoints (каждая используется 7 раз)
1. **Название:** cfgeventspawns: все 123 точки событий VehicleCrSk_* совпадают с 21 точкой VehicleSpawnPoints (каждая используется 7 раз)
2. **Критичность:** S3 (Средняя)
3. **Условия воспроизведения:** Скрипт Python: 144 pos, 21 уникальная пара (x,z); 41 событие по 3 точки, все из пула VehicleSpawnPoints. У эталона BI Черноруссии 54 общих из 552 точек (около 10%), здесь около 85%
4. **Причина:** НЕИЗВЕСТНО: гипотеза — точки скопированы из общего списка по ошибке, либо намеренно; при совпадении точек разные классы техники претендуют на одно место, CE может пропускать спавн или ставить машины друг на друга
5. **Файл и место:** rusforma_vehicles_cfgeventspawn:4-45 и 47-331
6. **Предлагаемое исправление:** Уточнить у заказчика намерение; при ошибке выдать каждому событию собственные точки (по эталону BI, где у событий почти все точки уникальны); проверить на тестовом сервере
7. **Повторное тестирование:** ещё не проводилось
