# Прототип P0: стрелок в люке Offroad_02

Одноразовый тестовый мод **HatchP0**. Проверяет, можно ли поставить игрока в люк ванильного M1025 так, чтобы он держался на ходу и стрелял из штатного оружия.

> ⚠️ Только для **DayZDiag_x64.exe**. На обычном клиенте и сервере мод ничего не делает (код под `#ifdef DIAG_DEVELOPER`). Не ставьте его на боевой сервер.

## Что уже известно из CrewFire

Мод CrewFire (ветка `claude/dayz-vehicle-shooting-animation-s15all`, стрельба из окна) по своему README проверен на DayZ 1.30. Его выводы закрывают главный вопрос P0:

* `LinkToLocalSpaceOf()` **держит** игрока у машины: до 120 км/ч, когда скорость задаёт скрипт, и до 72 км/ч на настоящем двигателе. Условия: гравитация и коллизия капсулы выключены, игрок перепривязывается, если его сдвинуло больше чем на 3 см.
* Штатное оружие работает. Патроны и координаты первой пули у сервера и клиента совпадают.
* **Опасно:** выстрел, который сразу попадает в машину, к которой привязан игрок, роняет игру, в том числе сервер. Стрелять из обычного кресла (`HumanCommandVehicle`) тоже нельзя: это тоже вылет.

P0 повторяет эту схему привязки и проверяет то, что относится именно к люку: точку на крыше, глубину, вид, безопасные углы стрельбы.

## Защита от вылета в P0

Пока игрок привязан, выстрел **блокируется** (сообщение в чате «Выстрел заблокирован: …»), если:
* ствол опущен ниже **−5°** от горизонта;
* голова меньше чем на **0,35 м** выше крыши;
* стойка не «стоя» (присесть и лечь в люке нельзя).

Не меняйте эти пороги без нужды: ниже них пуля может попасть в свою машину.

## Что проверяем

| Тест | Вопрос |
|---|---|
| **T1** | Держится ли игрок в точке люка стоя и на 20, 40 и 60 км/ч |
| **T2** | Стреляет ли оружие из люка; не мешает ли защита при нормальном прицеливании |
| **T3** | Держит ли движок игрока на крыше **без** привязки (в конфиге мода у Offroad_02 стоит `animPhysDetachSpeed = 30`) |
| **T4** | Как выглядит стрелок «по пояс в люке»; какая глубина правильная |
| **T5** | Не уходит ли игрок с точки при поворотах и стрельбе (счётчик `pins` в логе) |

## Установка

1. Скопируйте папку `prototype/@HatchP0` в папку игры DayZ (рядом с `DayZDiag_x64.exe`).
2. Запустите офлайн-миссию:
   ```
   DayZDiag_x64.exe -mod=@HatchP0 "-mission=.\Missions\dayzOffline.chernarusplus" -nosplash -noPause
   ```
   Если папки `Missions\dayzOffline.chernarusplus` нет, возьмите её из официального репозитория [DayZ-Central-Economy](https://github.com/BohemiaInteractive/DayZ-Central-Economy).
3. Признак, что мод загрузился: при нажатии `Ctrl+Num9` в чате появится строка `[HatchP0] ...`.

**Не запускайте вместе с CrewFire:** оба мода привязывают игрока к машине и будут мешать друг другу.

Готовый `HatchP0.pbo` собран без подписи скриптом `tools/pack_pbo.py`. Если игра его не примет, пересоберите:
```
python tools/pack_pbo.py prototype/HatchP0 prototype/@HatchP0/addons/HatchP0.pbo --prefix HatchP0
```
или соберите штатно через DayZ Tools → Addon Builder (исходная папка `prototype/HatchP0`, prefix `HatchP0`).

## Подготовка в игре

1. Встаньте на **длинную прямую дорогу**: автопилот едет строго прямо 15 секунд, на 60 км/ч это около 250 м.
2. Script Console → вкладка Enforce Script → вставить и запустить `tools/hmmwv_hatch/diag_offroad02_console.c`. Он поставит Offroad_02 в 6 м перед вами и заодно запишет в лог диагностику люка.
3. **До привязки** выдайте себе автомат (там же, в Script Console). Привязанный игрок считается «сидящим в машине», и брать предметы в руки игра ему не даст:
   ```c
   PlayerBase p = PlayerBase.Cast(GetGame().GetPlayer());
   EntityAI w = p.GetHumanInventory().CreateInHands("AKM");
   if (w) w.OnDebugSpawn();
   ```
4. Поверните машину носом вдоль дороги. Автопилот толкает её туда, куда она смотрит.

## Управление

Все команды: **левый Ctrl + клавиша цифрового блока** (NumLock включён).

| Клавиши | Действие |
|---|---|
| `Ctrl+Num1` | **LINK**: поставить в точку люка и привязать (схема CrewFire), ходьба блокируется сама |
| `Ctrl+Num2` | **PLACE**: поставить на крышу **без** привязки (T3) |
| `Ctrl+Num3` | **UNLINK**: отвязать, сбросить все режимы |
| `Ctrl+Num4` / `Num5` / `Num6` | автопилот 20 / 40 / 60 км/ч (автостоп через 15 с) |
| `Ctrl+Num0` | автопилот: плавная остановка |
| `Ctrl+Num7` | переключить «на крыше» / «в люке» (ноги на 1 м ниже крыши) |
| `Ctrl+Num8` | вкл/выкл блокировку ходьбы |
| `Ctrl+Num9` | **DUMP**: подробный срез состояния в лог |
| `Ctrl+Num+` / `Ctrl+Num-` | точка крепления выше / ниже на 0,1 м |

## Порядок теста

Перед каждым шагом и после него нажимайте `Ctrl+Num9`: это ставит метку в логе.

1. **T1 стоя.** `Ctrl+Num1`. Вы стоите на крыше над люком? Поверните мышью корпус на 360°.
2. **T4.** `Ctrl+Num7` (в люк). Посмотрите от третьего лица, как торчит персонаж. Подберите глубину `Ctrl+Num+`/`Num-` так, чтобы над крышей были грудь и руки с оружием. Запишите итоговое смещение из чата.
3. **T2 стоя.** Поднимите оружие (ПКМ), дайте очередь вперёд, в стороны и назад горизонтально. Затем опустите ствол вниз: выстрел должен заблокироваться с сообщением в чате.
4. **T1 + T2 на ходу.** `Ctrl+Num4` (20 км/ч): держитесь ли в люке, стреляется ли? Затем `Ctrl+Num0`. Повторите на `Ctrl+Num5` (40) и `Ctrl+Num6` (60).
5. **T3.** `Ctrl+Num3`, затем `Ctrl+Num2` (без привязки), затем `Ctrl+Num4`. Едет ли игрок вместе с машиной или соскальзывает?
6. В конце `Ctrl+Num3`.

### По желанию: проверка по сети

Это нужно, чтобы понять, как стрелка в люке видят **другие**. Запустите локальный диаг-сервер с этим модом (в `serverDZ.cfg` для теста `verifySignatures = 0`) и подключитесь клиентом DayZDiag с тем же `-mod=@HatchP0`. В P0 команды доходят до сервера через RPC, без синхронизации по шагу симуляции. Небольшие рывки здесь ожидаемы: в основном моде будет sync juncture, как в CrewFire.

## Что прислать

1. **Лог.** Файл `script_*.log` из `%LOCALAPPDATA%\DayZ\` (при тесте по сети ещё и лог сервера из папки `-profiles`). Достаточно строк с `[HATCHP0]` и `[HATCHDIAG]`.
2. **Короткий итог по каждому шагу:** держит, падает или дёргается; стреляется или блокируется; какая глубина выглядит правильно.
3. По возможности **скриншот** режима «в люке» от третьего лица.

## Как читать строки лога

Пример формата (значения условные):
```
[HATCHP0][OFFLINE] TICK cmd=MOVE linkedEnt=none floorEnt=none slidingOff=0 parent=Offroad_02 inVehicle=1 raised=1 speed=39.8kmh posMS=<…> drift=0.01m
[HATCHP0][OFFLINE]     testLinked=1 hatchMode=1 moveLock=1 solid=0 stance=0 aimUD=2.1 headAboveRoof=0.62m pins=14
```
* `parent=Offroad_02`: игрок привязан к машине. По опыту CrewFire так и должно быть: игрок остаётся дочерним объектом машины.
* `drift`: на сколько метров игрок сместился от точки крепления (норма до ~0,03 м, дальше срабатывает перепривязка).
* `pins`: сколько раз пришлось перепривязать. Растёт при поворотах; если растёт быстро на прямой, это повод разобраться.
* `aimUD` / `headAboveRoof`: угол ствола и высота головы над крышей, по ним работает защита от вылета.
* События: `EVENT_LINK_LOST` (привязка потеряна), `EVENT_DRIFT` (вытолкнуло дальше 0,8 м), `EVENT_COMMAND_CHANGED` (смерть, падение и т. п., игрок отвязан).
* `FIRE ...`: каждый выстрел с состоянием в этот момент.

## Что решает результат

| Результат | Что дальше |
|---|---|
| T1 и T2 работают до 60 км/ч, вид в люке нормальный | Делаем механику по плану на основе схемы CrewFire |
| Держит, но вид «в люке» плохой | Подбираем глубину и стойку; при необходимости своя поза, как в CrewFire |
| Защита блокирует нормальные выстрелы | Заменяем порог угла на точную проверку луча по геометрии машины |
| Не держит в точке люка | Смотрим лог: точка люка, перепривязка, геометрия крыши |
