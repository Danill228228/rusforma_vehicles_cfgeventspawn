# Разработка — соглашения

| Папка | Что хранится | Кто отвечает |
|---|---|---|
| `Source/<Мод>/` | исходники мода в структуре P:-диска: `config.cpp`, `scripts/3_Game|4_World|5_Mission`, `data/` | lead-engineer, config-build-engineer |
| `Scripts/` | служебные и экспериментальные скрипты (Python, bpy, проверочные) | все технические агенты |
| `Configs/` | эталоны и шаблоны конфигов и XML CE | config-build-engineer |
| `Models/<проект>/<объект>/` | `.blend`, скрипт генерации `build_*.py`, экспорт, README модели | modeler-3d |
| `Textures/<проект>/` | текстуры и маски, исходники в PNG/TGA | modeler-3d |
| `Builds/<мод>/` | `BUILD.md` (инструкция сборки), логи; бинарники PBO и ключи не коммитятся | config-build-engineer |

## Правила
- Префикс мода по умолчанию — `DZM_`: классы, RPC-идентификаторы, переменные, имена CfgPatches.
- Один мод — одна папка `Source/<Мод>/`. Её префикс PBO совпадает с путями в `files[]`.
- Скрипты не копируют ванильные методы целиком: `modded class` и вызов `super`.
- Секретов (ключ `.biprivatekey`, пароли) в репозитории нет. Подписывает заказчик на своём ПК.
- Крупные бинарники (больше 10 МБ) — через Git LFS или внешнее хранилище, по решению заказчика.
