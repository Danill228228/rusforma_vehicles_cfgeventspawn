# @RF_Humvee — отдельный мод DayZ

Свой HMMWV M1025 с открываемым люком стрелка на крыше — по образцу ванильного M1025 DayZ.

Модель своя: `RF_Humvee/source/m1025.py` строит кузов, капот с крыльями (откидывается вперёд, как у M1025),
4 двери, крышку багажника, салон, крышу с кольцом и крышкой люка. Размеры сняты в игре с ванильного M1025:
лучами по его геометрии (силуэт, крыша, перёд, зад) и через API машины (колёса, места экипажа, точки посадки, фары).
Ванильные модели не копируются.

От ванильного M1025 (`Offroad_02`) машина наследует то, что не видно глазами: двигатель, коробку, подвеску, звуки,
места и анимации экипажа, а колёса — ванильные колёса M1025 в своих слотах. Окраска — ванильные текстура и
материалы крыши M1025 (ссылками): зелёная у `RF_Humvee`, бежевая у `RF_Humvee_Desert`.

Двери, капот и багажник — анимированные части модели, а не детали-аттачменты: их не снять. Двигатель
(аккумулятор, свечи накала) доступен при открытом капоте, груз — при открытом багажнике, как у ванили.

| PBO | Что делает |
|---|---|
| `RF_Humvee.pbo` | машины `RF_Humvee` и `RF_Humvee_Desert`: модель, двери, капот, багажник, места, анимация люка |
| `RF_Humvee_Hatch.pbo` | действия «Открыть люк» / «Закрыть люк» из салона и снаружи (с крыши), сохранение положения люка после рестарта |

## Структура

```
RF_Humvee_Mod/
  @RF_Humvee/              ← готовый мод: копировать в папку DayZ и DayZServer
    mod.cpp
    Addons/RF_Humvee.pbo
    Addons/RF_Humvee_Hatch.pbo
  src/RF_Humvee/           ← исходники аддона (для Addon Builder / P:\)
    config.cpp                  машины (наследуют Offroad_02), окраска, зоны повреждений
    data/rf_humvee.p3d          своя модель M1025 (MLOD, открывается в Object Builder)
    data/model.cfg              колёса, амортизаторы, руль, двери, капот, багажник, люк
    data/rf_humvee_metal_*      матовый тёмный металл (рама, решётка, кенгурятник)
    scripts/4_World/RF_Humvee/RF_Humvee.c
  src/RF_Humvee_Hatch/     ← исходники аддона действий люка
  server/                  ← спавн: init.c (тест), cfgeventspawns/events/types
  tools/build_mod.py       ← пересобрать всё: python3 RF_Humvee_Mod/tools/build_mod.py
```

## Установка и проверка

1. Скопируйте папку `@RF_Humvee` в каталог **DayZ** (клиент) и в каталог **DayZServer**.
2. Без подписи в `serverDZ.cfg` поставьте `verifySignatures = 0;`, с подписью — см. ниже.
3. Сервер: `DayZServer_x64.exe -config=serverDZ.cfg -mod=@RF_Humvee -dologs -adminlog -scriptDebug=true`,
   клиент с тем же `-mod=@RF_Humvee` (в лаунчере: Моды → «Добавить локальный мод»).
4. Машина рядом с персонажем: функция из `server/init_c_test_spawn.c` (вставить в `init.c` миссии и вызвать в
   начале `StartingEquipSetup`). Она ставит машину с колёсами M1025, аккумулятором, свечами накала и фарами
   (`OnDebugSpawn`). Через админ-тулзу: заспавнить `RF_Humvee` и прикрепить 4× `Offroad_02_Wheel`, `CarBattery`,
   `GlowPlug`, 2× `HeadlightH7`.

Люк: в салоне в меню действий «Открыть люк» / «Закрыть люк» с любого места; снаружи — встать на крышу и смотреть
на крышку люка.

Не поворачивайте машину скриптом после создания (`SetOrientation` сразу после `CreateObjectEx`): этот поворот
до клиента не доходит, машина у игрока и на сервере стоит по-разному, и сервер отменяет посадку.

## Если что-то не так, пришлите мне логи

Файлы `*.RPT` и `script_*.log` из `%LocalAppData%\DayZ` (клиент) и из папки профиля сервера.

## Сборка через DayZ Tools (бинаризация, подпись)

1. DayZ Tools → **Work Drive** → смонтировать `P:`; скопировать `src/RF_Humvee` и `src/RF_Humvee_Hatch` в `P:\`.
2. **Addon Builder**: Source `P:\RF_Humvee`, Destination `@RF_Humvee\Addons`, включить *Binarize*,
   *Sign* (ключ создаётся в DS Utils). Повторить для `RF_Humvee_Hatch`.
3. Ключ `.bikey` положить в `DayZServer\keys`, и тогда можно вернуть `verifySignatures = 2`.

## Спавн на сервере постоянно

`server/cfgeventspawns_snippet.xml`, `events_snippet.xml`, `types_snippet.xml`: событие `VehicleRF_Humvee`.
Детали при спавне задаются в `cfgspawnabletypes.xml`: колёса `Offroad_02_Wheel`, `CarBattery`, `GlowPlug`,
`HeadlightH7` (дверей, капота и багажника-аттачментов у этой машины нет).
Тестовый спавн в `init.c` после проверки уберите.
