# Передача работы: люк HMMWV (Offroad_02) → сессия на ПК пользователя

Документ для сессии Claude, которая продолжит работу **на компьютере пользователя** (там есть DayZ, DayZDiag, DayZ Tools и папка `F:\Cloude\DayZMOD` с модом CrewFire). Облачная сессия, начавшая работу, к ПК доступа не имеет. Пользователь пишет по-русски.

## Задача

Мод для **ванильного** M1025 (`Offroad_02`, в 1.30 ещё `Offroad_02_Beige`): пассажир открывает верхний люк, поднимается в него и стреляет из штатного оружия (автоматы и винтовки), затем возвращается в машину.

Ограничения пользователя:
* не менять оригинальные PBO;
* не использовать сторонние модели и анимации (Expansion и т. п.);
* сохранить штатную физику, повреждения и места машины;
* не переходить к основному коду и анимациям, пока архитектура не подтверждена.

## Ключевые факты

* Модель: `\DZ\vehicles\wheeled\Offroad_02\Offroad_02.p3d` (`Addons\vehicles_wheeled.pbo`).
* В config.cpp и скриптах 1.30 **нет** AnimationSource люка. Есть ли скрытая анимация в самой модели, не проверено (это и проверяют `p3d_names.py` и диагностика).
* Места: 0 водитель, 1 передний пассажир, 2 задний левый, 3 задний правый. Для люка предложены задние места 2 и 3, не больше одного стрелка одновременно, место стрелка резервируется.
* Нельзя добавить новое место экипажа или анимацию в модель без её замены. Бинаризованные P3D не редактируются.

## Выводы из CrewFire (ветка `claude/dayz-vehicle-shooting-animation-s15all`)

CrewFire уже решает почти всё «механическое» (по его README, проверено на 1.30):
* выход из кресла: `ProcessLeaveEvents` → `CrewGetOut` → `StartCommand_Fall(0)` → `Land()`;
* крепление: гравитация и коллизия выкл → `LinkToLocalSpaceOf(car, m)` → перепривязка при сдвиге > 3 см;
* возврат: `UnlinkFromLocalSpace` → физика вкл → `StartCommand_Vehicle` + `SetVehicleType`;
* синхронизация: решение на сервере, `SendSyncJuncture`, выполнение в `ModCommandHandlerBefore`;
* защита от аварии, смерти и отключения; запрет посадки, прыжков и лазания; руки через `CanReceiveItemIntoHands`;
* **вылеты движка:** выстрел из `HumanCommandVehicle` и выстрел, сразу попадающий в машину, к которой привязан игрок.

## Отличия люка от окна (что придётся сделать иначе)

| | Окно (CrewFire) | Люк |
|---|---|---|
| Точка крепления | у двери, `CrewTransform` + сдвиг вбок | над задним отсеком: луч по крыше в точке люка (сейчас `dmgZone_roof`, уточнить по диагностике), ноги примерно на 1 м ниже крыши (подобрать в P0) |
| Поза | своя сидячая анимация (наклон в окно) | обычная стойка «стоя», своя анимация, скорее всего, не нужна |
| Стойка | принудительно присед (сидячие позы) | только «стоя»: присев, стрелок опустит ствол в крышу |
| Поворот корпуса | зафиксирован вдоль машины | свободный, 360° |
| Защита выстрела | сектор по горизонтали (40–140° в свою сторону) | ограничение по вертикали вниз, лучше точная проверка луча по геометрии машины |
| Стекло | разбивается при выходе | не нужно |
| Крышка | — | открыть анимацией, если она есть в модели; иначе решение пользователя (см. отчёт, раздел 9) |

3. **Прогнать P0** по `prototype/README.md` (без CrewFire в `-mod`). Можно автоматизировать так же, как `test/accept.ps1` в CrewFire.
4. **Доложить пользователю** результаты 2–3 и получить решение по архитектуре:
   * люк как режим внутри CrewFire (рекомендация: общий код выхода, крепления, возврата и защиты, без конфликтов) или отдельный мод;

5. Только после подтверждения писать основной код.
